# حافظ‌تیک — HafezTick

برنامه‌ریزی روزانه و هفتگی، تیک زدن کارها، و دیدن اینکه در گذر زمان چقدر به برنامه‌ات پایبند بوده‌ای.

حافظ‌تیک یک To-Do ساده نیست: هر روز که می‌آید، برنامه‌ی آن روز **ثبت و قفل** می‌شود، و آمار از روی همان سابقه‌ی واقعی ساخته می‌شود — نه از روی برنامه‌ی امروزِ تو.

---

## چه چیزی دارد

- **امروز** — حلقه‌ی پیشرفت روز، روتین‌ها و کارها، تیک زدن با انیمیشن، بازگردانی سریع، کارهای عقب‌افتاده
- **هفته** — تخته‌ی هفت‌روزه، نمره‌ی هفته، مقایسه با هفته‌ی قبل، سبد کارهای بی‌تاریخ
- **روتین‌ها** — تکرار روزانه / روزهای معیّن / «چند بار در هفته»، با درصد پایبندی ۳۰ روز اخیر
- **آمار** — زنجیره، نقشه‌ی پایبندی (heatmap)، نمودار روند با میانگین هفت‌روزه، مقایسه‌ی دوره‌ای، تفکیک دسته‌ها و روزهای هفته
- **تنظیمات** — تم روشن/تیره، هدف روزانه، روزهای استراحت، دسته‌ها، پشتیبان‌گیری و بازیابی

### تصمیم‌های محصولی که مهم‌اند

| تصمیم | چرا |
| --- | --- |
| برنامه‌ی هر روز هنگام رسیدن آن روز **ثبت می‌شود** | ویرایش یا حذف یک روتین، تاریخِ گذشته را بازنویسی نمی‌کند؛ «پایبندی» عدد صادقی می‌ماند |
| نمره‌ی روز **وزن‌دار** است (مهم ×۲، کم ×۰٫۵) | تمام کردن کار مهم باید بیشتر از پاک کردن کارهای آسان بیارزد |
| «امروز لازم نبود» کار را از **مخرج کسر** حذف می‌کند | کنار گذاشتن آگاهانه‌ی یک کار نباید شکست حساب شود |
| روتین «چند بار در هفته» نمره‌ی روز را پایین نمی‌آورد | تعهد هفتگی است، نه روزانه؛ UI هم نباید خلافش را القا کند |
| روزهای استراحت و روزِ بی‌برنامه، **زنجیره را نمی‌شکنند** | زنجیره باید انگیزه بدهد، نه اضطراب |
| امروزِ ناتمام هرگز زنجیره را نمی‌شکند | روز هنوز تمام نشده است |

## معماری

```
src/
  app/                 صفحه‌ها (App Router)
  components/
    ui/                اجزای پایه‌ی رابط کاربری
    layout/            پوسته، ناوبری، تم
    tasks/             تیک، ردیف کار، دیالوگ‌ها
    today/ week/       اجزای مخصوص هر صفحه
    charts/            نمودارهای SVG اختصاصی
  lib/
    date/              تقویم جلالی و ابزار روز (خالص، تست‌شده)
    domain/            مدل، زمان‌بندی، امتیازدهی، آمار (خالص، تست‌شده)
    storage/           Repository و آداپتور محلی
    store/             AppStore + اتصال React
```

**قاعده‌ی اصلی:** `lib/` هیچ چیزی از React یا DOM نمی‌داند. همه‌ی منطق — تبدیل تاریخ، ساخت برنامه‌ی روز، امتیاز، زنجیره، آمار — تابع خالص است و تست دارد. کامپوننت‌ها فقط نمایش می‌دهند و اکشن صدا می‌زنند.

### مدل داده

سه موجودیت اصلی، و یک واحد که همه‌چیز بر آن بنا شده است:

- `Routine` — کار تکرارشونده (قاعده‌ی تکرار)
- `Task` — کار یک‌بارمصرف (یک روز، یا سبد کارها)
- `Entry` — **واحدی که تیک می‌خورد و آمار روی آن ساخته می‌شود**

`Entry` عکسِ لحظه‌ای از برنامه است: وقتی روزی فرا می‌رسد ساخته می‌شود و بعد از آن دست‌نخورده می‌ماند. روزهای آینده فقط *پیش‌بینی* می‌شوند و چیزی ذخیره نمی‌شود تا وقتی کاربر واقعاً کاری با آن‌ها بکند.

### ذخیره‌سازی

فعلاً همه‌چیز محلی است (`localStorage`)، پشت یک `DataRepository`. هیچ حساب کاربری، هیچ سرور، هیچ هزینه‌ای. برای افزودن همگام‌سازی در آینده کافی است یک آداپتور تازه پیاده شود؛ رابط کاربری تغییری نمی‌کند.

### وابستگی‌ها

فقط Next.js، React و Tailwind. تقویم جلالی، نمودارها، آیکون‌ها، انیمیشن‌ها و اجزای رابط کاربری همگی داخل پروژه نوشته شده‌اند — سبک‌تر، قابل کنترل‌تر در RTL، و بدون ریسک وابستگی.
